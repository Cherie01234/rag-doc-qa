# 検索精度の評価（eval/）

RAG の「検索」部分が、質問に対して正しい根拠の箇所を上位に返せているかを測ります。
有料の API は使いません（埋め込みモデルはローカルで実行）。

## 中身

| ファイル | 内容 |
|---|---|
| `corpus/*.txt` | 評価用の日本語文書 13 本（約 11,000 文字） |
| `questions.jsonl` | 質問と正解の箇所の対 68 問 |
| `run_eval.py` | 評価スクリプト |
| `results.json` | 評価結果（条件ごとの指標と、質問ごとの正解の順位） |

## 評価用文書の出典とライセンス

`corpus/` の文書と `questions.jsonl` は、この評価のために新しく書いた**架空の**文書です（作成には AI エージェントを使用）。
社内規程・社内 FAQ・製品の取扱説明書・サービスの FAQ を模していますが、実在の企業・製品・サービスの文書ではなく、
書かれている数値や規則もすべて架空のものです。リポジトリ本体と同じ MIT License で公開します。

## 正解の決め方

`questions.jsonl` の1行が1問です。

```json
{"id": "q01", "question": "在宅勤務は1週間に何日までできますか？", "doc": "work_rules.txt", "evidence": "在宅勤務は週3日まで"}
```

- `doc`：答えが書かれている文書のファイル名
- `evidence`：答えの根拠になる文（文書中の文字列そのまま。文書の中に1回だけ現れる）

検索で返ったチャンクのうち、**`doc` の文書から取られ、`evidence` を丸ごと含むもの**を正解とみなします。
正解をチャンク番号ではなく文字列で持っているので、チャンクサイズを変えても同じ正解データで比べられます。
どのチャンクサイズでも `evidence` が分割で切れないこと（どれかのチャンクに丸ごと入ること）は `tests/test_eval.py` で確かめています。

## 測り方

1. `corpus/` の文書を、`ingest.py` と同じ `RecursiveCharacterTextSplitter` で分割する
2. `HuggingFaceEmbeddings` で埋め込み、`FAISS.from_documents` で索引を作る
3. 各質問で `similarity_search(k=10)` を実行する（文書での絞り込みなし＝アプリの「全PDF横断」と同じ）
4. 最初の正解チャンクの順位から、次の指標を計算する
   - **Hit@k**：上位 k 件に正解が入った質問の割合（k = 1, 3, 5, 10）
   - **MRR@10**：最初の正解の順位の逆数の平均（上位 10 件に無ければ 0）
   - 参考として、チャンクを無作為に並べた場合の Hit@k の期待値（`random_baseline`）も出す
   - 埋め込みが質問を区別できているかの目安として、1位になった回数が最も多いチャンクとその回数（`most_common_top1`）も記録する

比べる条件は、埋め込みモデル 2 種類 × チャンクサイズ 3 通り（300・500・800 文字、重なりはいずれも 100 文字）です。

| 埋め込みモデル | 説明 |
|---|---|
| `sentence-transformers/all-MiniLM-L6-v2` | アプリの現在の設定（`config.py`）。英語向け |
| `intfloat/multilingual-e5-small` | 多言語モデル。質問に `query: `、文書に `passage: ` を付けて埋め込む |

アプリの現在の設定（`all-MiniLM-L6-v2`・800 文字・重なり 100 文字）の結果には、`results.json` で `"is_app_setting": true` が付きます。

## 実行方法

```bash
pip install -r requirements.txt
python eval/run_eval.py          # 全条件を実行して eval/results.json を上書き
```

初回は埋め込みモデルをダウンロードします。ダウンロード後の実行は、作者の環境（CPU）で約30秒でした。
埋め込みは既定で CPU で計算します（`--device cuda` で変更可）。同じ環境で2回実行し、同じ結果になることを確かめています。

## 注意（この評価で言えること・言えないこと）

- 文書 13 本・質問 68 問の小さな評価です。チャンク数が少ないため、k が大きいと無作為でも当たりやすくなります（`random_baseline` を参照）
- チャンクサイズが違うとチャンク数も違うので、同じ k でもチャンクサイズ間の比較は条件がそろっていません。大きいチャンクは当たりやすい代わりに、LLM に渡す文字数が増えます
- 文書と質問を同じ作り手が書いているため、実際の利用者の質問より答えやすい可能性があります
- 測っているのは検索だけです。LLM が生成する回答の正しさは評価していません
